# ADR-027: Writing Exercise Eligibility and Independent Revalidation

> **Status:** Accepted (Product Owner task T029)
> **Date:** 2026-10-25

---

## Context

RCA-004 found four stored writing exercises whose W08 review came from the
model that generated them. They were offered to students. The stored
records must stay unchanged (history, revisions, tutor-only references,
generation attempts), and the bank must keep a minimum eligible inventory.

---

## Decision

### Eligibility

- `writing.eligibility_event` is an append-only history per exercise
  (`quarantined` or `eligible`, reason, source, validation ID). The latest
  event decides; an exercise without events is eligible. Nothing is
  deleted or rewritten.
- Student lists, level counts and seeding inventories show eligible
  exercises only. A quarantined exercise returns 404 to the student unless
  the student already submitted it (then it stays readable with its
  feedback); drafts and submissions to it are refused (409). Stored drafts,
  submissions, evaluations and the tutor queue are unaffected.

### Independent revalidation (`app/writing/revalidation.py`)

- The revision students see is checked against the current contract and
  deterministic checks (`revisions.checks_for`), then reviewed with the
  review prompt and keys of its exercise type.
- The generator is **excluded** from routing (`route(exclude=…)`), not only
  tried last. No other model available, an exhausted budget or a truncated
  review means `unavailable`; the exercise stays quarantined.
- Every revalidation is stored in `writing.independent_validation`
  (version, models, checks, review, reasons, calls, tokens, cost); a
  database constraint forbids `passed` with the generator as reviewer. Only
  `passed` appends an `eligible` event.
- Minimum eligible inventory: L1 3, L2 3, L3 3, L4 1. Nivel 1 replacements
  are generated by the existing seeding only when L1 is below it.

### Prevention (all levels)

- Generation reviews (`generation.py` L2–L5, `editing.py` L1) exclude the
  generator; `same_model_review` remains as a second defense.
- L1 reviews get their own output limit (6000 tokens): at 3000 the only
  independent reviewer truncated four of six L1 reviews, which is how the
  generator ended up reviewing them.

---

## Consequences

- With one working independent reviewer, a reviewer outage leaves
  exercises quarantined and can leave an inventory gap; this is reported,
  never bypassed.
- `route(exclude=…)` is a new optional parameter; multiple-choice callers
  are unchanged.
